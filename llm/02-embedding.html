嵌入向量Embedding

token ID 只是字典裡的編號，本身沒有意義。這一章看模型如何把編號「查表」換成一串數字，讓意思相近的詞在空間中彼此靠近，再替每個位置蓋上座標章。

      § 2.1從編號到向量：查表

      經過第 01 章的分詞，「我喜歡喝咖啡」變成了一串整數，例如 [2385, 10421, 6789, 31842]。但 31842 並不比 2385「大」或「更重要」——它們只是字典裡的頁碼。

      模型手上有一張嵌入矩陣 E：每個 token 在裡面都有專屬的一列，列的長度 d 就是嵌入維度。「嵌入」這一步沒有任何乘法運算，就是拿 ID 當索引，把那一列取出來。以 GPT-2 為例，E 有 50,257 列、每列 768 維，光這張表就有 3,800 多萬個參數。

      x = E[ id ] = onehot(id) · E
      // 數學上等價於「one-hot 向量 × 矩陣」，實作上直接用索引取列，省下大量乘法

      § 2.2意義就是座標：語意空間

      剛初始化時，嵌入矩陣只是一堆隨機數字。訓練過程中，模型為了更準確地預測下一個 token，會不斷微調每一列。結果是：出現在相似上下文的詞，向量會被推到相近的位置。「貓」和「狗」常出現在「餵＿吃飯」、「我家的＿很可愛」這類句子裡，於是它們的向量越來越像。

      語言學家 J. R. Firth 有句名言：「你可以從一個詞的鄰居認識它。」這正是嵌入向量背後的分布假說。

      要衡量兩個向量有多像，最常用的是餘弦相似度：只看方向、不看長度。方向一致為 1，垂直為 0，完全相反為 −1。

      cos θ = ( a · b ) / ( ‖a‖ ‖b‖ )

      § 2.3方向也有意義：國王 − 男人 + 女人

      2013 年 word2vec 的研究發現一個驚人的現象：嵌入空間中的方向能編碼關係。從「男人」指向「女人」的向量，和從「國王」指向「女王」的向量幾乎平行——「性別」在空間裡是一個固定的方向。

      所以拿「國王」的向量，減掉「男人」、加上「女人」，落點最接近的詞就是「女王」。同樣的手法也適用於「東京 − 日本 + 法國 ≈ 巴黎」這類首都關係。

      註

      現代 LLM 的嵌入不一定像 word2vec 那樣有乾淨的線性關係，而且 token 常是半個詞或一個字。但「相近意義 → 相近向量」的直覺依然成立，後續的注意力層會在這個基礎上依上下文再加工。

      § 2.4位置從哪裡來：位置編碼

      查表得到的向量只描述「這是哪個 token」，不包含「它在第幾個位置」。下一章的自注意力會把所有 token 一視同仁地兩兩比較——如果不另外提供位置資訊，「狗咬人」和「人咬狗」在模型眼中就是同一袋字。

      原始 Transformer 的做法是替每個位置算出一個正弦位置編碼，直接加到嵌入向量上。不同維度用不同頻率的 sin／cos 波：前面的維度變化快，像時鐘的秒針；後面的維度變化慢，像時針。組合起來，每個位置都得到一組獨一無二的「指紋」。

      PE(pos, 2i) = sin( pos / 100002i/d )
      PE(pos, 2i+1) = cos( pos / 100002i/d )
      // 模型實際的輸入：x = E[id] + PE(pos)

      § 2.5本章重點

      1. token ID 只是編號；嵌入層用它當索引，從嵌入矩陣 E 取出對應的一列向量。
      2. 嵌入矩陣是可訓練的參數，訓練後意義相近的詞會在空間中彼此靠近。
      3. 餘弦相似度只看方向，是比較兩個向量最常用的方式。
      4. 空間中的方向可以編碼關係，例如「國王 − 男人 + 女人 ≈ 女王」。
      5. 注意力本身不分先後，必須加上位置編碼，模型才知道 token 的順序。
